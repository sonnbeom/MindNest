# Before / After 비교 예시

> 생성일: 2026-05-14 12:18  
> RAG 적용 전/후 동일 입력에 대한 LLM 응답 품질 비교  
> 측정 기준: counter_hints 구체성 / fact 정확도 / interpretation 정확도

---

## 비교 기준

| 항목 | Before (RAG 없음) | After (RAG 적용) |
|------|-------------------|-----------------|
| 인지 왜곡 인식 | 일반적인 부정적 사고로 처리 | 특정 왜곡 유형에 맞는 분석 |
| counter_hints | 막연한 반례 | 해당 왜곡·상황에 특화된 반례 |
| 재구성 문장 | 일반적인 위로성 문장 | 왜곡 유형 맞춤 CBT 재구성 |

## case_01 — 직장/성과 — 낙인 찍기

**입력:**
> 오늘 발표에서 말이 꼬였어. 나는 역시 안 되는 사람이야. 이런 것도 제대로 못 하다니.

**Before (RAG 없음):**
```json
{
  "thoughts": [
    "나는 역시 안 되는 사람이다",
    "나는 이런 것도 제대로 못 한다"
  ],
  "fact": "오늘 발표에서 말이 꼬였다",
  "interpretation": "한 번의 실수가 자신의 능력 전체를 정의한다",
  "counter_hints": [
    "이전 발표나 성공 경험 떠올리기",
    "말이 꼬인 구체적 원인 분석",
    "발표 전체를 평가하기"
  ],
  "current_actions": [
    "발표에 참여함",
    "실수를 인식하고 돌아봄"
  ]
}
```

**After (RAG 적용):**
```json
{
  "thoughts": [
    "나는 안 되는 사람이다",
    "나는 발표를 제대로 못한다"
  ],
  "fact": "오늘 발표 중 말이 꼬이는 상황이 발생했다",
  "interpretation": "말이 꼬인 것이 내가 안 되는 사람임을 증명한다",
  "counter_hints": [
    "한 번의 실수와 전체 능력은 다름",
    "누구나 긴장 시 말이 꼬일 수 있음",
    "발표 자체를 시도했다는 사실"
  ],
  "current_actions": [
    "발표에 직접 도전함",
    "상황을 돌아보며 성찰 중"
  ]
}
```

**차이점:**

- **counter_hints Before:** 이전 발표나 성공 경험 떠올리기 / 말이 꼬인 구체적 원인 분석 / 발표 전체를 평가하기
- **counter_hints After:**  한 번의 실수와 전체 능력은 다름 / 누구나 긴장 시 말이 꼬일 수 있음 / 발표 자체를 시도했다는 사실
- **fact Before:** 오늘 발표에서 말이 꼬였다
- **fact After:**  오늘 발표 중 말이 꼬이는 상황이 발생했다

## case_02 — 직장/성과 — 흑백논리

**입력:**
> 보고서 한 군데 틀렸어. 완벽하게 못 하면 하나마나지. 팀장한테 칭찬도 못 받았고.

**Before (RAG 없음):**
```json
{
  "thoughts": [
    "나는 완벽하지 못했다",
    "나는 인정받지 못했다"
  ],
  "fact": "보고서에서 한 부분이 틀렸고, 팀장으로부터 칭찬을 받지 않았다",
  "interpretation": "한 곳의 실수가 전체 성과를 무의미하게 만들고, 칭찬 부재가 노력을 부정한다고 해석",
  "counter_hints": [
    "대부분이 정확했을 가능성",
    "개선 기회로 보기",
    "침묵이 부정을 의미하지 않을 수 있음"
  ],
  "current_actions": [
    "보고서 작성 완료",
    "실수 인식 및 점검"
  ]
}
```

**After (RAG 적용):**
```json
{
  "thoughts": [
    "나는 실패한 사람인 것 같다",
    "나는 인정받지 못하는 것 같다"
  ],
  "fact": "보고서 한 곳이 틀렸고, 팀장의 칭찬을 받지 못했다",
  "interpretation": "한 곳의 실수가 보고서 전체를 무의미하게 만든다",
  "counter_hints": [
    "부분 실수와 전체 실패의 차이",
    "칭찬 없음이 부정은 아님",
    "수정 가능한 실수임"
  ],
  "current_actions": [
    "보고서 작성 완료",
    "팀장에게 제출함"
  ]
}
```

**차이점:**

- **counter_hints Before:** 대부분이 정확했을 가능성 / 개선 기회로 보기 / 침묵이 부정을 의미하지 않을 수 있음
- **counter_hints After:**  부분 실수와 전체 실패의 차이 / 칭찬 없음이 부정은 아님 / 수정 가능한 실수임
- **fact Before:** 보고서에서 한 부분이 틀렸고, 팀장으로부터 칭찬을 받지 않았다
- **fact After:**  보고서 한 곳이 틀렸고, 팀장의 칭찬을 받지 못했다

## case_03 — 직장/성과 — 성급한 결론

**입력:**
> 팀장이 오늘 내 의견을 또 무시했어. 어차피 내가 뭘 말해도 달라지는 게 없을 거야.

**Before (RAG 없음):**
```json
{
  "thoughts": [
    "나는 팀장에게 무시당하고 있다",
    "나는 의견을 말해도 소용없다"
  ],
  "fact": "팀장이 오늘 당신의 의견에 대해 반응하지 않았다",
  "interpretation": "그 반응을 무시로 해석하고, 미래도 같을 것으로 예측",
  "counter_hints": [
    "팀장의 침묵 이유를 확실히 알 수 있는가",
    "과거에 의견이 반영된 경험",
    "다른 방식의 전달 시도 가능성"
  ],
  "current_actions": [
    "의견을 말하려는 시도",
    "상황을 객관적으로 인지"
  ]
}
```

**After (RAG 적용):**
```json
{
  "thoughts": [
    "나는 팀에서 무시당하는 것 같다",
    "나는 아무것도 바꿀 수 없다"
  ],
  "fact": "오늘 팀장이 내 의견을 채택하지 않았다",
  "interpretation": "어떤 의견을 내도 영원히 달라지지 않을 것이다",
  "counter_hints": [
    "과거 의견이 반영된 순간",
    "팀장 외 다른 영향 경로",
    "의견 표현 방식 변화 가능성"
  ],
  "current_actions": [
    "팀 회의에서 의견 제시",
    "상황을 객관적으로 인식"
  ]
}
```

**차이점:**

- **counter_hints Before:** 팀장의 침묵 이유를 확실히 알 수 있는가 / 과거에 의견이 반영된 경험 / 다른 방식의 전달 시도 가능성
- **counter_hints After:**  과거 의견이 반영된 순간 / 팀장 외 다른 영향 경로 / 의견 표현 방식 변화 가능성
- **fact Before:** 팀장이 오늘 당신의 의견에 대해 반응하지 않았다
- **fact After:**  오늘 팀장이 내 의견을 채택하지 않았다

## case_04 — 인간관계 — 낙인 찍기

**입력:**
> 친구가 연락을 안 해. 나는 원래 매력 없는 사람이라서 그런 것 같아. 항상 내가 먼저 연락해야 해.

**Before (RAG 없음):**
```json
{
  "thoughts": [
    "나는 매력 없는 사람인 것 같다",
    "나는 항상 먼저 연락해야 한다"
  ],
  "fact": "친구가 최근 연락을 하지 않았다",
  "interpretation": "친구의 미연락 = 자신의 매력 부족",
  "counter_hints": [
    "친구의 바쁜 일정이나 상황 변화",
    "관계 형태에 따른 연락 빈도 차이",
    "과거 상호 연락 패턴의 재검토"
  ],
  "current_actions": [
    "친구와의 관계 유지 시도",
    "상대를 먼저 배려하는 행동"
  ]
}
```

**After (RAG 적용):**
```json
{
  "thoughts": [
    "나는 매력 없는 사람이다",
    "나는 항상 먼저 연락해야 한다"
  ],
  "fact": "친구가 먼저 연락을 하지 않고 있다",
  "interpretation": "내가 매력 없기 때문에 연락이 없다고 판단함",
  "counter_hints": [
    "친구의 개인 사정 가능성",
    "먼저 연락하는 사람의 용기",
    "관계를 소중히 여기는 증거"
  ],
  "current_actions": [
    "관계 유지를 위한 노력",
    "감정을 인식하고 표현함"
  ]
}
```

**차이점:**

- **counter_hints Before:** 친구의 바쁜 일정이나 상황 변화 / 관계 형태에 따른 연락 빈도 차이 / 과거 상호 연락 패턴의 재검토
- **counter_hints After:**  친구의 개인 사정 가능성 / 먼저 연락하는 사람의 용기 / 관계를 소중히 여기는 증거
- **fact Before:** 친구가 최근 연락을 하지 않았다
- **fact After:**  친구가 먼저 연락을 하지 않고 있다

## case_05 — 인간관계 — 지나친 일반화

**입력:**
> 소개팅에서 또 거절당했어. 나는 사람들한테 항상 별로인가봐. 이번이 세 번째야.

```json
  "fact": "소개팅에서 3번 거절당했다",
  "interpretation": "거절 경험들을 자신의 근본적 가치 판단으로 일반화함",

    "거절이 상대방과의 '맞지 않음'일 수 있음",
    "한 번의 상황이 전체를 대표하지 않음",
    "소개팅 자체가 확률 게임일 수 있음"
  ],
  "current_actions": [
    "소개팅 기회에 참여하기",

  ]
}
```

**After (RAG 적용):**

```json
{

}
```

- **counter_hints After:**  소개팅 궁합은 양방향 요소 / 세 번은 전체 관계의 극히 일부 / 거절한 상대방의 개인 상황 가능성
- **fact Before:** 소개팅에서 3번 거절당했다
- **fact After:**  소개팅에서 세 번 거절을 경험했다
